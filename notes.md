# Заметки по экспериментам

## 2026-10-24 — фиксируем GPT-2 бейзлайн

Останавливаемся на текущем GPT-2 как на исходной модели для последующих
экспериментов с reward model и RL. Дополнительный подбор архитектуры пока
откладываем: обучение и оценка работают, сравнение с простыми стратегиями проведено.

### Конфигурация

- Данные: первые 1000 пользовательских историй из `listens.parquet`.
- Разбиение по общим временным границам: `train_end=20799987`, `val_end=23399983`.
  Пользователи без train-истории исключаются; после фильтрации остаётся 901 пользователь.
- Словарь строится только по train, минимальная частота трека — 5 взаимодействий.
  В словаре 86 239 треков и два специальных токена: PAD и UNK.
- GPT-2 со случайной инициализацией: 2 слоя, 4 головы, размерность 128, окно 64.
- AdamW: learning rate `3e-4`, weight decay `0.01`, batch size 32, seed 42.
- Обучение: 5 эпох. Для оценки выбран `best.pt` по минимальному validation loss.
- Папка запуска: `artifacts/baseline_t4_1000_minfreq5/`.
  Модель используем вместе с её `vocab.pkl` и `experiment_config.json`.

### Протокол сравнения

Один пример на пользователя: предсказываем первый трек test по истории train + val.
В оценке 897 пользователей с непустой test-историей. GPT-2 использует последние
64 взаимодействия. Кандидаты — все реальные треки сохранённого словаря;
PAD и UNK исключены, повторные рекомендации знакомых треков разрешены.

Неизвестные целевые треки не удаляем из оценки, а учитываем как промахи.
Их доля — 30,7%. Recall, NDCG и MAP усредняем по тем же примерам для всех стратегий.
Поскольку правильный трек в каждом примере один, Recall@K здесь совпадает с HitRate@K.

Сравниваем с двумя стратегиями без обучения:

- **Popularity:** один общий топ по частотам взаимодействий в train.
- **Personal frequency:** личный топ по всей истории train + val; при нехватке
  треков дополняем общим топом без повторов.

Обе стратегии используют тот же словарь кандидатов, что и GPT-2.

### Вывод и дальнейшие действия

GPT-2 заметно превосходит общую популярность, но примерно соответствует личным
частотам. При K=20 это 85 попаданий против 84 у личных частот и 14 у общей
популярности. Личные частоты дают более высокие NDCG@20 и MAP@20, то есть по этим
метрикам располагают правильные треки выше. При K=10 GPT-2 получает 64 попадания
против 59 у личных частот.

Убедительного преимущества последовательной модели над личными частотами пока
нет. Один запуск и 897 примеров не позволяют считать небольшие различия устойчивыми;
статистическую значимость не проверяли. Также личные частоты используют всю историю,
а GPT-2 — окно из 64 взаимодействий.

Фиксируем этот результат как отправную точку, а не как оптимальную модель.
Следующий этап — обучение и оценка reward model, затем RL-дообучение GPT-2.
Сравнение до и после RL проводим с теми же данными, словарём и протоколом оценки;
простые стратегии оставляем в итоговой таблице.

## 2026-10-24 — сравнение вариантов reward model

Цель — предсказать `played_ratio_pct / 100` для пары «предыдущая история + трек».
Значения выше 1 не обрезаем. MAE и RMSE ниже приведены в процентных пунктах.

### Данные и признаки

Используем тот же исходный набор из 1000 пользователей, сохранённые временные
границы и словарь GPT-2 с минимальной частотой трека 5. Равномерно выбираем
20 000 train-взаимодействий, 5000 validation и 5000 test; seed 42.
Все варианты сравниваются на одних и тех же примерах.

В reward-оценку включаем только взаимодействия с целевым треком из словаря
и доступной предшествующей историей. Это отличается от оценки рекомендаций,
где неизвестные целевые треки учитываются как промахи. Неизвестные треки
в контексте reward model остаются UNK.

Сравнили четыре варианта:

1. **GPT-2 + Ridge:** линейная регрессия с L2-регуляризацией на 128 признаках
   замороженного GPT-2. Используем представление последней позиции в последовательности
   «история + оцениваемый трек». Alpha выбираем из `0.1, 1, 10, 100` по validation MAE;
   в этом запуске выбрана `0.1`. Решатель — SVD.
2. **GPT-2 + CatBoost:** те же 128 признаков, вместо Ridge — CatBoost.
3. **GPT-2 + stats + CatBoost:** к 128 признакам добавлены пять новых, итого 133.
4. **Stats + CatBoost:** только пять новых признаков, без представлений GPT-2.

Дополнительные признаки:

- длительность оцениваемого трека;
- средняя доля прослушивания трека по предшествующим train-событиям;
- средняя доля прослушивания пользователя по его предыдущей истории;
- число предыдущих прослушиваний этого трека пользователем;
- доля предыдущих прослушиваний пользователя с `played_ratio_pct < 50`.

Исторические статистики используют события строго раньше timestamp текущего
взаимодействия; события с тем же timestamp исключены. Текущий отклик и будущие
события в признаки не попадают. Длительность считаем доступным свойством трека.
Если у трека нет прошлого train-отклика, используем среднее по предшествующему train;
если прошлого нет вообще — 0.5. Для пользователя без прошлого используем среднее
0.5 и долю коротких прослушиваний 0.

Для всех вариантов CatBoost: до 500 деревьев, depth 6, learning rate 0.05,
loss RMSE, early stopping по validation MAE с ожиданием 50 итераций, seed 42.
GPT-2 не дообучается. Test не используется для выбора alpha и числа деревьев.

### Результаты последнего запуска

| Модель | Val MAE | Val RMSE | Test MAE | Test RMSE |
|---|---:|---:|---:|---:|
| Общее среднее train-подвыборки | 42.3388 | 44.5202 | 42.2497 | 44.4259 |
| Средний отклик трека по полному train | 39.1407 | 43.6341 | 39.0110 | 43.7621 |
| GPT-2 + Ridge | 38.9362 | 42.6202 | 38.6076 | 42.5819 |
| GPT-2 + CatBoost | 37.8394 | 41.6770 | 37.7106 | 41.6526 |
| GPT-2 + stats + CatBoost | **32.9898** | **38.8271** | **33.0898** | **39.1145** |
| Stats + CatBoost | 33.1248 | 39.0329 | 33.2312 | 39.3852 |

### Выводы

CatBoost на замороженных признаках GPT-2 немного лучше Ridge. Основное улучшение
даёт добавление исторических статистик: test MAE снижается с 37.71 до 33.09 п.п.

Модель только на пяти новых признаках почти повторяет результат объединённой:
33.23 против 33.09 п.п. MAE. Добавление представлений GPT-2 даёт всего около
0.14 п.п. улучшения; устойчивость разницы и статистическую значимость не проверяли.
При этом вариант без GPT-признаков проще и дешевле при применении.

Ошибка около 33 п.п. остаётся большой. Эти результаты подтверждают пользу признаков,
но сами по себе не доказывают, что reward model правильно ранжирует альтернативные
рекомендации для одного пользователя. Все оценки получены на реально прослушанных
треках, а при RL модель будет оценивать и предложенные политикой объекты.

## 2026-10-24 — план RL и использование статей

Из статьи [Aligning GPTRec with Beyond-Accuracy Goals with Reinforcement
Learning](https://arxiv.org/pdf/2403.04875) берём методологию экспериментов:

- Последовательно генерируем список: каждый следующий трек учитывает уже
  сгенерированные рекомендации.
- Пробуем разные функции вознаграждения и исследуем изменения поведения.
  Для нашей работы планируем награду по CatBoost и варианты со штрафами
  за повторы и популярность; конкретные формулы ещё предстоит зафиксировать.
- Сравниваем награду, релевантность и разнообразие до и после RL,
  исследуем компромисс между ними.

В первой статье используется PPO. Для первого нашего эксперимента выбираем
более простой REINFORCE на рекомендациях, сгенерированных текущей GPT-2,
с фиксированной reward model и ограничением отклонения от исходного бейзлайна.
Это адаптация постановки, а не полное воспроизведение метода статьи.
Дополнительный обучаемый critic, необходимый для описанного в статье PPO,
пока не вводим; CatBoost предсказывает отклик и не заменяет такой critic.

Вторая статья — [Session-Level Optimization for Large-Scale Retrieval using
REINFORCE with Multi-Step Off-Policy Correction](https://arxiv.org/pdf/2607.02818).
В ней REINFORCE обучается на записанных взаимодействиях с поправками на
различие политик. Наш план с генерацией действий и оценкой через CatBoost
отличается от этого подхода; использование REINFORCE само по себе не означает
воспроизведение второй статьи.

RL-эксперименты должны ответить на все пять вопросов задания:

1. Как изменились награда и поведение: популярность, длительность, знакомые
   треки и повторы в рекомендациях.
2. Сохранилась ли релевантность по Recall@K, NDCG@K, MAP@K; как изменились
   покрытие каталога и сходство рекомендаций разных пользователей.
3. Какие сигналы подходят для продолжения взаимодействий и возвращаемости,
   что можно проверить офлайн и какие выводы требуют онлайн-проверки.
4. Что происходит при генерации пяти треков вместо одного: награда и повторы
   по шагам, отклонение сгенерированного контекста от реальной истории.
5. Как разные награды и сила ограничения отклонения от бейзлайна влияют
   на компромисс между релевантностью и вознаграждением.

Генерацию списка отличаем от моделирования реальных взаимодействий:
рекомендованный трек не означает прослушанный. Текущий CatBoost не моделирует
завершение сессии или возвращение пользователя; сумма предсказанных долей
прослушивания не доказывает улучшение долгосрочных целей. Протокол обновления
исторических признаков для нескольких сгенерированных шагов определим отдельно.
Этот раздел фиксирует план; RL-обучение ещё не реализовано и не запускалось.


## 2026-10-24 — реализован первый RL-цикл

В `src/reinforce.py` добавлен REINFORCE для одного следующего трека.
В `experiment.ipynb` — загрузка двух отдельных копий исходного бейзлайна,
подготовка контекстов и явная ячейка запуска обучения.

Контексты выбираются перед известными реальными треками тем же способом,
что и для reward model. Фактический следующий трек и его отклик не участвуют
в REINFORCE-loss: действие сэмплируется из текущей политики по всему словарю
реальных треков, исключая PAD и UNK. Обучающие контексты берём только из train;
для validation добавляем train-префикс. Test в RL-цикле не используется.

Оптимизируем:

`loss = -mean((reward - baseline_reward) * log_prob(action)) + kl_coef * KL(policy || reference)`.

Контекстный baseline — награда жадного действия исходной GPT-2 по той же
функции награды. Он не зависит от сэмплированного действия. KL считается точно
по распределениям реальных треков. Dropout отключён у обеих GPT-2, но градиенты
обучаемой политики сохраняются. Исходная модель остаётся замороженной и также
даёт эмбеддинги для неизменяемого CatBoost.

Доступны функции награды:

- `listening`: предсказанная доля прослушивания;
- `repeat_penalty`: прогноз минус `penalty`, если трек уже встречался в полной истории;
- `popularity_penalty`: прогноз минус `penalty * train_count / max_train_count`.

Стартовые настройки в `RL_PARAMS`: 5000 train-контекстов, 512 validation,
2 эпохи, batch size 32, AdamW с lr `1e-5`, weight decay `0.01`, clipping `1.0`,
`kl_coef=0.05`, `penalty=0.1`, seed 42. Это начальные параметры для отладки,
не результат подбора. Каждый вариант награды запускается заново с исходного
бейзлайна; имя папки по умолчанию `artifacts/rl_<reward_type>_seed42/`.

Validation-контексты и seed сэмплирования фиксированы. Лучший чекпоинт выбирается
по `val_reward - kl_coef * val_kl`, включая исходную эпоху 0.
В папке запуска сохраняются словарь, конфиг, история, `checkpoints/best.pt`
и `checkpoints/latest.pt`. Эти веса загружаются существующим `load_model`.
Выбор по модельной награде не заменяет последующее сравнение релевантности,
повторов и разнообразия при одинаковом протоколе.
